# P1.5 · 本地 LLM 改写引擎

**适用场景**：分数 ≥ 0.85 / `saturated` 段，规则引擎改不动，必须重写语域才能跨阈值。

## 为什么需要 LLM 改写

`aigc.cmd rewrite` 是规则引擎，天花板 0.98（见 P2 末尾"饱和段的天花板"）。要真正跨过阈值，需要用**本地 1.7B 改写模型 + 同一个 aigc_zh_v3** 的闭环——它判分用的就是本技能的 P2 检测器，所以改完的数字直接可比，不需要换算。

## 模型信息

| 项 | 值 |
|---|---|
| 模型 | `qwen3-merged-aigc_zhv3-Q4_K_M.gguf`（1.7B / Q4_K_M / 1.03 GB） |
| 端点 | `http://127.0.0.1:11103`，api key 固定，配置里 `local_fixed: true` |
| 位置 | `Paper-LocalAI\local-ai\`（自带 `llama-server.exe` + ggml/vulkan 运行库） |
| 速度 | 单段 1–2 秒；52 段全文约 200 秒（CPU/Vulkan） |
| 擅长 | 书面语 → 口语化的语域迁移，正是 `aigc_zh_v3` 唯一认的东西 |
| 不擅长 | 术语/公式/法条密集段（同一段连改三次会越改越高） |

## 使用方法

```bat
set P=E:\E-Apps\Work TOOL\论文\Paper-LocalAI

:: 1) 起模型（固定 127.0.0.1:11103；已在跑会直接返回 already running）
%P%\start-local.cmd

:: 2) 看分数 + 最可疑的段
cd /d %P%\agent-harness
python -m cli_anything.paper aigc 论文.docx --top 12 --json

:: 3) 先预演：这一轮会动哪几段（文献/表格/公式/英文/封面自动跳过）
python -m cli_anything.paper aigc 论文.docx --loop 2 --per-round 6 --dry-run

:: 4) 真跑闭环：改写 → 复检 → 直到 ai_ratio <= target 或用完轮数
python -m cli_anything.paper aigc 论文.docx --loop 3 --target 0.20 -o 优化版.docx --json
```

## 实测效果

实测（16.5k 字真论文，见 `references/measured.md` 第 9 节）：**64.5% → 18.5%**，99 段里 48 段被改动、**全部下降、0 段上升**，38 段跨过阈值，字数只 +0.3%。

## 改写手法的唯一有效解

**有效手法**：动词落地（采用→搭起来、负责→管、具有→挑），一句一个动作，用"先…再…最后 / 要…就得 / 缺的正是"串联。

**无效手法**：同义词替换、拆长句、加细节、补例证（与规则引擎的天花板一致，全都停在 0.98+）。

## 四类句式踩了就反弹

（v21 / v24 两轮实测）：

1. 评价/推论句——「后者偏大，说明……」「两个水平都偏低，实际应用时要往保守一侧修」
2. 「不是 A 而是 B」
3. 破折号收束——「——这一步就落到技术观测上」
4. 排比式收尾——「投时打底，链路补偿跟上，解算收尾」

## 段号口径

`paper aigc` 把 docx 转成空行分隔文本，再用检测器的 `split_paragraphs`（min 20 字）切段，与 `aigc.cmd detect -f 论文.txt` 完全一致。

**注意**：`aigc.cmd detect -f 论文.docx` 会合并成大块（最长块上千字，模型 `max_len=500` 只截前面），分数会假降——要逐段比，两边都得走"空行分隔 txt"这条路。

## 坑点

- **P1.5 的服务器别用 `start` / `Start-Process` 拉**：会继承调用方的 Job Object，脚本一结束就被连带杀掉（表现为"刚 [ok] 就没了"）。`start-local.cmd` 内部走 WMI（`local-ai\_spawn.ps1`），进程挂在 `WmiPrvSE` 下才活得久。
- **端口会漂**：GUI 那个离线版每次启动都换端口和 key（实测 11103 → 39676）。要走 GUI 就让它自动发现；要稳定就用 `start-local.cmd` + `paper auth set --local-fixed` 钉死 11103。
